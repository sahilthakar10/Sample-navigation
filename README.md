# Navigation Showcase — Native (Nav2) ⇄ CMP (Nav3) across Android, iOS & shared

A Compose Multiplatform sample that demonstrates the exact navigation architecture
used in a large KMP app: a **native navigation graph** (Android Nav2 / iOS UIKit)
that hosts a **shared CMP navigation graph** (Navigation-3 style), with the two
worlds communicating **only via deep links**.

> The shared "CMP nav core" here is a tiny, dependency-light re-implementation of
> `androidx.navigation3` (`NavKey`, `NavBackStack`, `NavDisplay`, `entry<>`). The deep link
> `CmpNavigationRoute` / `CmpDeepLinkResolver` / `CmpNavSerializers` are **generated at build
> time by a real KSP processor** (`:shared-ksp`) from the `@CmpDeepLink` annotations — exactly
> like `sfl-cmp-navigation-ksp` in the real app, ktor `Url` and all. Every file notes the
> real-app class it mirrors.

## The scenarios it demonstrates

| # | Scenario | Where to tap | What happens under the hood |
|---|----------|--------------|------------------------------|
| 1 | **Native → CMP** | Native Home → "Open IPO Home" | `navController.navigate("ipo/home?…")` matches a `cmpNavGraph` destination → `CmpRouteScreen` → `CmpDeepLinkResolver.resolve()` → `CmpNavigationHost` |
| 2 | **CMP → CMP** | IPO Home → "Open IPO: TATA-TECH" | `backStack.add(IpoRoute.Detail(...))` — native never sees this hop |
| 3 | **CMP → CMP → CMP** | IPO Detail → "Open another IPO" | another `backStack.add(...)`; native stack still has ONE entry |
| 4 | **CMP → Native** | IPO Detail → "View Scrip Details" | `onHostNavigation(ScripDetailsRoute.detailsPage(...))` → host pushes a native screen |
| 5 | **CMP → External URL** | IPO Detail → "Open NSE website" | `onHostNavigation(HostNavigation.ExternalUri(...))` |
| 6 | **CMP → exit to Native** | any CMP screen → "Back" on the root entry | `backStack.popOrExit { onHostNavigation(OnExit) }` |
| 7 | **App-wide deep link from shared code** | Profile → "Fire app deep link via IKNDeepLinkBridge" | shared `ProfileViewModel` calls `IKNDeepLinkBridge.navigateAppDeeplink(...)`, resolved per platform |
| 8 | **Compile-time DI (Metro) + assisted injection** | Native Home → "Open Orders" → tap an order | `OrderListPresenter` is constructor-injected; `OrderDetailPresenter` is built via **assisted injection** with the NavKey's `orderId` (Metro `@DependencyGraph`, compile-time-validated) |

## The one source of truth

Every deep link is defined once via `@CmpDeepLink` on a `NavKey` route. The `:shared-ksp`
KSP processor scans those annotations at build time and generates:
- `CmpNavigationRoute` — URL builders + `deeplinkUris` (WRITE side).
- `CmpDeepLinkResolver` — `resolve()` / `hasDeeplink()` using ktor `Url` (READ side, the
  single decision point for "is this a CMP route?").
- `cmpSerializersModule` — polymorphic `NavKey` serializers.

Add a new `@CmpDeepLink` route and all three regenerate automatically — no hand-editing.

## Run — iOS

Requirements: **full Xcode** (not just Command Line Tools). On this build machine only
Command Line Tools were present, so the Kotlin/Native *frontend compiles* (validated:
`./gradlew :shared:compileKotlinIosSimulatorArm64`) but the final framework link + app
build must be done where Xcode is installed.

```bash
# 1) Point to full Xcode
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

# 2) Open the iOS project (the framework is built automatically by a Run Script build phase)
open iosApp/iosApp.xcodeproj

# 3) Pick an iPhone simulator and Run.
```

If Xcode reports the `.xcodeproj` needs finalizing, create a fresh iOS App target
(SwiftUI, bundle id `com.example.navigation.iosApp`), add the four Swift files in
`iosApp/iosApp/`, set `INFOPLIST_FILE = iosApp/Info.plist`, add the framework search
path `$(SRCROOT)/../shared/build/xcode-frameworks/$(CONFIGURATION)/$(SDK_NAME)`, and add
a Run Script phase running `./gradlew :shared:embedAndSignAppleFrameworkForXcode`.

Test a **system deep link** into CMP:

```bash
xcrun simctl openurl booted "navsample://app/oiAnalysis/home?instrumentId=NIFTY&source=sim"
```

## Key takeaways it makes visible

- The native graph and CMP graph are **separate back stacks**; the CMP graph is **nested
  as a single node** inside the native graph. Native sees the whole CMP flow as one entry.
- They communicate **only via deep link strings**. Registration (`CmpNavigationRoute`) and
  resolution (`CmpDeepLinkResolver`) come from the same `@CmpDeepLink` source, so they can't drift.
- CMP→CMP is pure shared Kotlin (`backStack.add`); CMP→native/external is the `HostNavigation`
  bridge; app-wide deep links from shared code use `IKNDeepLinkBridge` (DI, per-platform impl).
